# Line Balance Chart (Takt Studio)

เว็บแอปทำ Line Balance / Man-Machine Chart / Standard Work Chart / Forecast และ Work Load
ไม่ต้อง build อัปโหลดขึ้น host (เช่น GitHub Pages) ได้เลย เข้าด้วยชื่อผู้ใช้ + รหัสผ่าน และบันทึกงานอัตโนมัติลง Supabase

## ไฟล์ใน repo
```
index.html             แอปทั้งหมดในไฟล์เดียว (โค้ด, CSS, config ฝังอยู่ข้างใน)
sw.js                  Service worker (ติดตั้งเป็นแอป / เปิดได้แม้เน็ตหลุด)
manifest.webmanifest   ข้อมูลติดตั้งแอป
icon-*.png, apple-touch-icon.png, favicon-32.png, icon.svg   ไอคอนแอป (วางที่ root เดียวกับ index.html)
supabase/              ไฟล์ SQL ตั้งค่าฐานข้อมูล (ดูลำดับด้านล่าง)
tests.js + package.json  ชุดทดสอบ (npm install แล้ว npm test)
.gitignore, README.md
```
Supabase URL และ anon key อยู่ในส่วน `config.js` ที่ฝังใน `index.html` (anon key ใส่ใน repo public ได้เพราะป้องกันด้วย RLS ห้ามใส่ service_role key)

## ลำดับการทำงานที่แนะนำ (เมนูเลข 1–5)
1. **Forecast และ Work Load** ใส่ยอดผลิตและเวลาทำงาน ได้ Takt Time (= เวลาทำงาน ÷ ยอดผลิต)
2. **สร้างจาก Process Flow** แตกงานย่อย ใส่เวลา ให้ระบบจัดคนและสถานี
3. **Line Balance และ Man-Machine** ดูโหลดต่อคน คอขวด Yamazumi และข้อเสนอแนะ
4. **เทียบ Manual กับ Robot**
5. **Standard Work Chart** ทำเอกสารมาตรฐานเป็นขั้นสุดท้าย

ไม่มียอด Forecast ก็ข้ามข้อ 1 ได้ โดยใส่ Takt ตรงๆ ในข้อ 2

## ตั้งค่าครั้งแรก
รัน SQL ใน Supabase (SQL Editor) ตามลำดับ:
`schema.sql` → `shared.sql` → `versions.sql` → `roles_trash.sql` → `backup_logs.sql`
(`shared.sql` ใช้ปรับตารางเดิมให้แชร์งานข้ามบัญชี ดูหัวไฟล์ก่อนรันว่าจำเป็นกับ project ของพี่หรือไม่)

**เพิ่มผู้ใช้:** Authentication → Users → Add user → Create new user
- Email พิมพ์ `ชื่อผู้ใช้@lb.local` เช่น `bee@lb.local` ตั้งรหัสผ่าน และติ๊ก **Auto Confirm User**
- ผู้ใช้เข้าเว็บพิมพ์แค่ `bee` กับรหัสผ่าน
- ปิดการสมัครเอง: Authentication → Sign In / Providers → ปิด **Allow new users to sign up**

## สิทธิ์ผู้ใช้
- **ผู้แก้ไข (editor)** บันทึก แก้ ลบเข้าถังขยะ กู้คืน ลบถาวรได้
- **ผู้ดูอย่างเดียว (viewer)** ดู ลองสมมติ ส่งออกได้ แต่แก้/บันทึก/ลบไม่ได้ (ฐานข้อมูลบล็อกด้วย RLS)
- ผู้ใช้ที่ไม่มีแถวใน `lb_roles` เป็นผู้ดูอย่างเดียวอัตโนมัติ ผู้ใช้ใหม่หลังรัน SQL ต้องเพิ่มสิทธิ์เอง (คำสั่งอยู่ท้าย `roles_trash.sql`)
- งานที่ลบอยู่ในถังขยะ 30 วันแล้วลบถาวรเอง

## สำรองข้อมูลและ log
- สำรองอัตโนมัติทุกวัน 03:00 (เวลาไทย) ลงตาราง `lb_backups` เก็บ 30 วัน วิธีกู้อยู่ท้าย `backup_logs.sql`
- Error ของหน้าเว็บส่งลงตาราง `lb_errors` (เก็บ 90 วัน ไม่เกิน 5 รายการต่อการเปิดหน้า) ดูที่ Table Editor
- ในหน้าต่าง "งานที่บันทึกไว้" มีปุ่มดาวน์โหลดสำรองทุกงาน (.json) ควรเก็บไว้นอกระบบเป็นระยะ เพราะสำรองอัตโนมัติอยู่ในฐานข้อมูลเดียวกัน

## ฟีเจอร์อื่น
- **วิธีใช้ 3 ขั้นตอน** ปุ่มบนหน้าแรกและไอคอน ? ที่แถบบน เปิดหน้าต่างอธิบายลำดับการใช้งานกับศัพท์ Takt Time / Cycle Time / Yamazumi (แก้ข้อความที่ `<dialog id="helpDlg">` ใน `index.html`)
- **Forecast: ดูผลรายชิ้นงาน (Part)** ที่หัวข้อ “ผล Work Load เทียบ N” ช่อง “ดูผลของ” เลือกได้ทั้งทุกไลน์รวม รายไลน์ หรือรายชิ้นงาน (จัดกลุ่มตามไลน์ แสดงเฉพาะชิ้นงานที่มียอด)
- เมนูที่ยังไม่มีข้อมูลงานจะขึ้นข้อความบอกเหตุผล แทนที่จะเป็นหน้าเริ่มต้นเฉยๆ
- **ส่งออกรายงาน PDF / รูป** กรอกชื่อบริษัท โลโก้ ผู้จัดทำ ผู้ตรวจสอบ ได้ (PDF ใช้ Save as PDF ขนาด A4 แนวนอน)
- **Realtime** แสดงว่าใครเปิดหรือแก้งานอยู่ และแจ้งเมื่อมีคนบันทึกงานเดียวกัน (ใช้ Supabase Realtime ไม่ต้องรัน SQL เพิ่ม)
- **มือถือ / ติดตั้งเป็นแอป** Android/Chrome กด "ติดตั้งแอป" ที่แถบบน, iPhone ใช้ Safari → แชร์ → เพิ่มลงในหน้าจอโฮม (ต้องเปิดผ่าน https)
- ไลบรารี Excel โหลดเฉพาะตอนใช้ ครั้งแรกที่กดอาจรอครู่หนึ่ง

## แก้ไขและอัปเดต
- แก้โค้ดที่ `index.html` ที่เดียว แล้วรัน `npm test` ก่อนอัปโหลด
- ถ้าเพิ่ม/ลบไฟล์ในรายการ `SHELL` ของ `sw.js` ให้เปลี่ยนเลข `CACHE` (เช่น `lb-v7`) เพื่อให้เครื่องที่ติดตั้งแอปไว้อัปเดตทันที
